# 🛵 FoodGo — แอปเดลิเวอรี่ครบ 3 ฝั่ง

แอปเดลิเวอรี่จำลองสไตล์ LineMan/GrabFood เขียนด้วย Flutter ล้วน
ไม่ต้องใช้เซิร์ฟเวอร์ ไม่ต้องต่อเน็ต ไม่ต้องลง package เพิ่ม

## เริ่มใช้งาน

เปิด PowerShell แล้วรัน 3 คำสั่งนี้ทีละบรรทัด

```powershell
cd C:\Users\BANK\Desktop\moblie\foodgo
flutter create --project-name foodgo --platforms=android,web .
flutter run -d chrome
```

คำสั่งกลางคือการสร้างโฟลเดอร์ `android/` `web/` ที่ Flutter ต้องใช้
มันจะ **ไม่ทับ** ไฟล์ใน `lib/` กับ `pubspec.yaml` ที่มีอยู่แล้ว

> อยากรันบน Android emulator แทนเว็บ ให้ใช้ `flutter run` เฉย ๆ
> (ต้องลง Android Studio ก่อน)

## เข้าแอปครั้งแรก

จะเจอหน้าล็อกอินก่อน — ใส่เบอร์อะไรก็ได้ 10 หลัก แล้ว **รหัส OTP คือ `123456`**
หรือกด "ข้ามไปก่อน (โหมดทดลอง)" เข้าได้เลย

## ลองเล่นให้ครบวงจร

จุดสำคัญของแอปนี้คือ **ทั้ง 3 ฝั่งใช้ข้อมูลชุดเดียวกัน**
สั่งจากฝั่งลูกค้า แล้วออเดอร์จะไปโผล่ที่ฝั่งร้านและฝั่งไรเดอร์ทันที

ลองตามนี้

1. หน้าแรกเลือก **ลูกค้า** → เลือกร้าน `ครัวป้าแดง ข้าวมันไก่`
2. กดเมนู → เลือกจำนวน ใส่หมายเหตุ → ใส่ตะกร้า
3. กดปุ่มตะกร้าลอย → ไปชำระเงิน → ใส่โค้ด `FOODGO50` → กดสั่ง
4. จะเด้งเข้าหน้าติดตามสถานะ ดูไทม์ไลน์ขยับเอง
5. กดย้อนกลับจนถึงหน้าเลือกบทบาท → เข้า **ร้านค้า** จะเห็นออเดอร์เดียวกันรออยู่
6. เข้า **ไรเดอร์** จะเห็นงานเดียวกันนั้นให้กดรับ

### อยากกดเองทีละขั้น

หน้าเลือกบทบาทมีสวิตช์ **"จำลองสถานะอัตโนมัติ"** — ปิดมันซะ
แล้วสถานะจะไม่ขยับเอง ต้องไปกดที่ฝั่งร้าน (รับออเดอร์ → เริ่มปรุง → อาหารพร้อม)
และฝั่งไรเดอร์ (รับงาน → รับอาหาร → ออกเดินทาง → ส่งถึงแล้ว)

## ฟีเจอร์

**ทั่วไป**
ล็อกอินด้วยเบอร์ + OTP · แจ้งเตือนแบบมีกระดิ่งนับเลข · แชทกับไรเดอร์และร้าน ·
กระเป๋าเงิน (เติมเงิน จ่ายด้วย wallet ประวัติธุรกรรม) ·
แผนที่จำลองที่หมุดไรเดอร์วิ่งจริงตามสถานะออเดอร์

**ฝั่งลูกค้า**
แบนเนอร์โปรเลื่อนเอง · หมวดหมู่แบบวงกลม · ดีลเด็ดเลื่อนแนวนอน ·
รายการร้าน · ค้นหา (ชื่อร้าน/หมวด/ชื่อเมนู) · ร้านโปรด ·
เมนูแบ่งหมวด · เลือกจำนวน+หมายเหตุ · ตะกร้าทีละร้าน · โค้ดส่วนลด ·
เลือกที่อยู่/วิธีจ่าย · ติดตามสถานะแบบไทม์ไลน์+แผนที่ · ยกเลิกออเดอร์ · ให้ดาว · ประวัติ

**ฝั่งไรเดอร์**
เปิด-ปิดรับงาน · รายการงานว่างพร้อมค่ารอบ · จุดรับ-จุดส่ง ·
กดเดินขั้นตอนรับ-ส่ง · แจ้งเก็บเงินปลายทาง · สรุปรายได้และประวัติงาน

**ฝั่งร้านค้า**
ออเดอร์ใหม่/กำลังทำ/เสร็จแล้ว · รับหรือปฏิเสธออเดอร์ · เริ่มปรุง → อาหารพร้อม ·
เปิด-ปิดร้าน · จัดการเมนู (เปิด-ปิดขาย แก้ราคา เพิ่ม ลบ) · ยอดขาย · เมนูขายดี

## โครงสร้างไฟล์

```
lib/
├── main.dart              จุดเริ่มต้นแอป
├── role_select_page.dart  หน้าเลือกบทบาท
├── models.dart            โมเดลข้อมูล (ร้าน เมนู ตะกร้า ออเดอร์ สถานะ)
├── store.dart             ⭐ ศูนย์กลางข้อมูล + logic ทั้งหมด
├── mock_data.dart         ข้อมูลร้านจำลอง — แก้ตรงนี้ถ้าอยากเพิ่มร้าน
├── theme.dart             สี ธีม ฟังก์ชันจัดรูปแบบเงิน/เวลา
├── widgets/common.dart    วิดเจ็ตที่ใช้ซ้ำหลายที่
├── customer/              9 หน้าฝั่งลูกค้า
├── driver/                ฝั่งไรเดอร์
└── merchant/              ฝั่งร้านค้า
```

**ไฟล์ที่ควรอ่านก่อน** คือ `store.dart` — ตรรกะทั้งแอปอยู่ในนี้
ทุกหน้าจอแค่อ่านค่าจากมันแล้ววาด UI

## อยากแก้อะไรต่อ

| อยากทำ | แก้ที่ |
|---|---|
| เพิ่มร้าน / เพิ่มเมนู | `mock_data.dart` |
| เปลี่ยนรูปอาหาร | วางไฟล์ใน `assets/images/` แล้วอ้างใน `mock_data.dart` |
| เปลี่ยนสีแอป | `theme.dart` → `AppColors` |
| เปลี่ยนขั้นตอนสถานะออเดอร์ | `models.dart` → `OrderStatus` + `Order.flow` |
| เปลี่ยนความเร็วการจำลอง | `store.dart` → `Timer.periodic` และตัวเลข `elapsed` |
| เพิ่มโค้ดส่วนลด | `mock_data.dart` → `promoCodes` |

## ข้อจำกัด

ข้อมูลเก็บในหน่วยความจำอย่างเดียว **ปิดแอปแล้วข้อมูลหาย**
ถ้าอยากให้ข้อมูลอยู่ถาวรและใช้ได้หลายเครื่องจริง ๆ ขั้นต่อไปคือต่อ Firebase
(Firestore เก็บออเดอร์ + Auth ล็อกอิน) หรือเขียน backend เอง
